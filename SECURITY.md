# Security policy

## Reporting

Report a vulnerability privately through GitHub's "Report a vulnerability" (Security tab of this repository), not in
a public issue. Expect an answer within a week. Fixes ship as a patch release through the normal rc → promote path. A
release found to be unsafe after it shipped gets the catalog's `bad` flag: Arcade Tools stops offering it and tells
installed copies to roll back.

## What Arcade Look guards, and how

Look opens files from anywhere: downloads, mail attachments, archives. Treat every file it previews as untrusted.

| Surface | Protection | Tested by |
|---|---|---|
| Files you preview | Look only reads a previewed file: it never writes to, renames or deletes one. Archives, Office, OpenDocument and EPUB files, tables, RTF, Markdown, images, fonts and audio tags are read by Rust code in Look's own process (there is no separate sandbox process); PDFs by pdf.js in the window (form scripting and XFA are off), and video and audio by the system's web view. A panic inside a reader becomes a preview error, not a crash. Archive previews are bounded: a listing stops at 50,000 entries or 2.5 s, and one entry is extracted at a time, to at most 1 GiB and within 30 s, into Look's cache folder under a plain file name (folder parts and `..` dropped, reserved characters such as `:` replaced), so nothing is written outside the cache. The cache is the person's own (`~/.cache/arcade-look` on Linux), and folders older than a day are removed at start. The Office, slide and table readers also cap the HTML they build, the images they inline, and the slides, rows and cell text they show. | `src-tauri/src/archive.rs` (`zip_slip_is_neutralised`, `entries_that_sanitize_alike_keep_their_own_contents`, `a_slow_member_cannot_hold_a_tar_listing_past_its_budget`, `garbage_is_an_error_not_a_panic`), `src-tauri/src/util.rs` (`panics_become_errors`, `extracted_files_stay_in_the_users_own_cache`). Not covered by a test: that a previewed file is never written, the entry and extraction caps, and the Office, slide and table caps. |
| Previewed documents | Markdown, Word, OpenDocument, EPUB and notebook output become HTML that the window rebuilds from an allow-list: no script, style, frame, object, form, SVG or media element, no event handler or style attribute, and links only to web and mail addresses, in-page anchors and local files (which Look then previews). HTML files and plugin HTML output show in a frame with `sandbox=""` (no scripts, forms, popups or same-origin access) and a policy that also blocks script, objects and form posts. A link opens in the system browser only on a click, and only `http`, `https` and `mailto` do. **Not blocked:** an `https` image in a document is fetched when the document is shown, which tells that server the file was opened; `http` images and every other remote kind of content are refused by the window's policy. | `scripts/ui-checks/sanitize.mjs` (all six checks: "the sanitiser keeps no script, frame, form, style or media element", "the sanitiser keeps only web, mail and in-page links", "the sanitiser keeps the content of a dropped wrapper and the text of a kept one", "images: https is kept …", "the HTML preview frame is fully sandboxed and its policy comes before any document script", "a script in an HTML preview does not run"), `src-tauri/src/commands.rs` (`open_url_takes_web_and_mail_links_only`), `src-tauri/tests/security_config.rs` (`only_images_may_come_from_the_web`) |
| Windows | The preview and Settings windows load only Look's own bundled files, under a Content-Security-Policy: scripts only from those files and from the folders of installed script plugins (through `alook://`), with no `unsafe-inline` or `unsafe-eval` (WebAssembly may compile, for the PDF decoders); no objects or plugins; connections only to Tauri's IPC, the `alook://` file protocol and Look's loopback media server. `withGlobalTauri` is off. The windows hold only Tauri's core, open-file dialog, notification and window permissions: the file-system, shell, HTTP, process and updater plugins are not built in, and the opener plugin is reachable only through Look's own `open_default`, `open_url` and `reveal` commands. Look's commands take any path the window names: the window runs only Look's own code and the plugins the person installed. | `src-tauri/tests/security_config.rs` (`csp_runs_only_looks_own_scripts_and_no_plugins_objects`, `only_images_may_come_from_the_web`, `the_webview_gets_only_core_dialog_notification_and_window_permissions`) |
| Local file serving | `alook://` serves files, decoded images and plugin assets to Look's own windows only, with ranged reads. A plugin asset URL is refused if it contains `..`, however written. On Linux, audio and video play from a loopback HTTP server on 127.0.0.1 and a random port; it answers only GET and HEAD and only URLs carrying a random per-run token (from `/dev/urandom`), so another local user or a web page cannot use it to read files. | `src-tauri/src/protocol.rs` (`ranges`, `serves_ranges`, `plugin_routes_refuse_parent_folders`), `src-tauri/src/mediaserver.rs` (`serves_ranges_with_token`) |
| Plugins | Plugins are programs and scripts the person puts in Look's plugins folder; Look installs and downloads none, and the "Enable plugins" setting (on by default) turns them all off. They are **not sandboxed**: a command plugin is an ordinary child process with the person's rights (run directly, never through a shell, with the file's path as one argument, in its own process group, 15 s by default and then the whole group is killed, at most 64 MiB of output kept), and a script plugin is a module running in the preview window with the same access as Look's own code. Install only plugins you trust. HTML and Markdown a plugin produces go through the same sandbox and allow-list as documents. | `src-tauri/src/plugins.rs` (`runs_command_plugin`: arguments, timeout, a command that leaves a process behind, a changed program or file is not served from the cache), `src-tauri/src/protocol.rs` (`plugin_routes_refuse_parent_folders`). Not covered by a test: the output cap and the "Enable plugins" switch. |
| Link IPC | Arcade Link's sockets (0600, peer UID check, per-endpoint token). Look offers `look.preview` (opens the files or `file://` addresses it is given, nothing else) and `look.inspect` (read-only file facts), and on Windows and macOS `look.preview_selection`. Look sends a file to another Arcade app only when the person picks an action in the strip, only to an installed Arcade app whose own manifest offers that action, and not when "Connect with other Arcade apps" or that app is turned off; the private folder it renders a PDF page into for that (0700, the file 0600) is removed afterwards. | Link's own tests, `src-tauri/src/link.rs` (`preview_accepts_file_urls_only`), `src-tauri/tests/link_consumer.rs` (`peers_first_later_missing_disabled_and_featured_limit`, `clipboard_size_unavailable_private_and_secret_guards`, `wheel_gets_current_file_and_lens_handoffs_are_private_and_removed`; run in CI inside Link's isolated runner) |
| File manager integration | On Linux, GNOME Files asks Look to preview a file over the user's session D-Bus (`org.gnome.NautilusPreviewer`); the call only opens a preview, and Look stays out of the way if another previewer owns the name. On Windows and macOS the selection shortcut asks Explorer or Finder (a fixed AppleScript) for the selected paths. Nothing is executed or changed. | Not covered by a test (needs a desktop; `scripts/verify-resident.py` and `scripts/verify-appimage.py` run the packaged app, not these calls). |
| Child processes | Besides plugin commands: other Arcade apps' launchers from Link's registry (when the person opens an app or uses an action), Look's own launcher on Restart, the system's opener for "Open with default app", "Show in folder" and web links, and the system tools the integration calls with fixed arguments (`update-desktop-database` on Linux, `reg` and `taskkill` on Windows, `osascript` and `kill -0` on macOS). No file name or content is put into a shell command. "Open with default app" hands the previewed file to the operating system exactly as double-clicking it would (so an executable would start), and happens only on the person's Enter, Ctrl/Cmd+O or click. | `src-tauri/src/plugins.rs` (`runs_command_plugin`) for plugins. Not covered by a test: the others. |
| Clipboard and screen | Look never reads the clipboard and never captures the screen. It writes the clipboard only when the person copies a file path or the diagnostics text. A PDF page is rendered to an image for another Arcade app only when the person sends it. | Not covered by a test. |
| Network | Look's own code makes no network connection: no telemetry, update check or lookup, and its Cargo manifest lists no HTTP or TLS client. Web links open in the system browser on a click. The window may fetch `https` images a document refers to (see Previewed documents). | `src-tauri/tests/security_config.rs` (`looks_own_code_has_no_http_or_tls_client`, `only_images_may_come_from_the_web`) |
| Settings backup and restore | The settings Tools exports and imports are a short allow-list (theme, idle time, global shortcut, text and highlight limits, autoplay, show hidden files): plugins, window state, peer choices and caches are never in it, unknown fields are rejected, the shortcut must be in its canonical form, and a file over 1 MiB is refused. | `src-tauri/src/portable_settings.rs` (`portable_allowlist_excludes_local_and_device_settings`, `import_rejects_unknown_fields_and_noncanonical_shortcuts`). Not covered by a test: the 1 MiB limit. |
| Logs and crash reports | Look has no crash reporter. Panics in a reader become a preview error; warnings and errors from the window are written to a local log (`arcade-look.log` in Look's data folder, rotated at a size cap), one bounded line each, and never sent anywhere (when Look is started from a terminal they stay on the terminal). "Copy diagnostics" copies the app, version, channel, OS, desktop and Link status, with no file names or content; the person pastes it into an issue themselves. | `src-tauri/src/commands.rs` (`warnings_and_errors_are_logged_on_one_line`). Not covered by a test: the diagnostics text. |
| Updates | Look is installed and updated by Arcade Tools, which trusts a release only through its signed `manifest.json` (see Arcade Tools' SECURITY.md). Look has no updater of its own, and Settings points to Tools. | Arcade Tools' tests, `scripts/ui-checks/behaviour.mjs` ("LK-9: Settings shows labelled sections and leaves updates to Tools"), `src-tauri/tests/security_config.rs` (`the_webview_gets_only_core_dialog_notification_and_window_permissions` checks that no updater plugin is built in) |

## Dependencies

`cargo deny check` (advisories, licences, bans, sources) runs in CI as the `deny` job, which a release also waits for;
Dependabot watches Cargo, npm and GitHub Actions. `npm audit --omit=dev` reports nothing. An advisory with a fixed
release is fixed, not accepted. The accepted ones are listed with a reason in `deny.toml` and in `docs/v1/DECISIONS.md`
(D16): "unmaintained" notices (no known vulnerability) for crates that come through Tauri's Linux stack (gtk-rs 0.18's
macros, urlpattern's `unic-*` crates), zbus 5 (zvariant, zbus_names), `paste` (build-time macros of lofty and exr) and
`ttf-parser`, which Look uses to read font metadata (it forbids unsafe code and a panic is a preview error; moving to
`skrifa` is a rewrite of `font.rs` and is not scheduled); and one unsound iterator in glib 0.18 (`VariantStrIter`),
which only `Variant::array_iter_str` builds, and nothing in Look's dependency tree calls it. The fix needs gtk-rs 0.20,
which Tauri 2 does not use yet.

Third-party licences are in `THIRD_PARTY_NOTICES.md`, which is bundled with every package and opened from Settings →
About: Rust crates, JavaScript packages, pdf.js's decoders and fonts, Inter, the files vendored from Arcade Link, and
the native libraries in the Linux AppImage (`scripts/notices.py`, `scripts/native-notices.py`; CI fails when the file
is out of date).
